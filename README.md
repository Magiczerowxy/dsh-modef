# @magiczerowxy/dsh-modef

模型选择 + 推理强度滑块 for DeepSeek Harness。模型保持官方下拉菜单，推理强度改为 Claude 风格滑块；最高档带可选动画特效，全部配置集中在**设置 → 插件 → 插件配置**的「高级推理等级滑块」卡片中。

A model picker + reasoning-effort slider for the DeepSeek Harness web UI. Keeps the model as the official dropdown, replaces the effort control with a Claude-style slider, and adds selectable max-tier animations — all configured from one card in **Settings → Plugins → Plugin configuration**.

## 版本兼容 Compatibility

**本版本（0.9.0）适配 DSH 0.1.7-rc.1 与 0.2.0-rc.1 / rc.2。** 0.2.0-rc.1 **没有**改动 0.1.7-rc.1 那三处插件契约（下表），但它把**清单兼容闸门**变成了硬门槛，**peer 范围写不对 = 插件整个消失**，而且**不报错** —— 升级后插件不见了，先看这一节。

### 0.2.0-rc.1：peer 范围就是开关（不满足 = 插件整个被跳过）

0.2.0-rc.1 组合 profile 时对每个 bundle 跑一次 `evaluatePluginCompatibility`（`@deepseek-ai/dsh-app-boot`）：把该包 `peerDependencies` 里**所有** `@deepseek-ai/dsh` / `@deepseek-ai/dsh-*` 的范围，拿**正在运行的 dsh 版本**去套 semver（`{ includePrerelease: true }`），**只要有一个不满足就抛错，并把整个 bundle 从这一层里跳过**（`loadProfileDirectory` 的 try/catch → `skippedBundles`）。后果是**静默的**：

| 你会看到 | 你看不到 |
| --- | --- |
| 模型选择器变回官方样式、设置里没有本卡片 | 界面**没有任何报错**；只有启动 stderr 一行 `skipping profile bundle "…": Plugin …@… is incompatible with dsh 0.2.0-rc.1: peerDependencies …`，桌面版启动看不到 |
| 插件的 slot、设置文档、卡片**全都不存在** | 不是「卡片挂了」，是这个条目**根本没进组合树**（host 的配置目录里也查不到 `dsh-modef`） |

本仓库**真的踩了这个坑**：升级后六个 dsh peer 全都停在 `^0.1.1-rc.2 || ^0.1.5-rc.1 || ^0.1.7-rc.1`。对 0.x 来说 `^0.1.7-rc.1` 的上界是 `0.2.0`，而 `0.2.0-rc.1 < 0.2.0` —— 看起来该通过，但 semver 对**预发布版**另有一条限制：带预发布段的版本，只有在范围里存在**同 `[major, minor, patch]` 且同样带预发布段**的 comparator 时才可能被接受（`includePrerelease` 也不解除这条），所以 `0.2.0-rc.1` **一个都满足不了**。用 0.2.0-rc.1 自带的 semver 实测：

```
satisfies("0.2.0-rc.1", "^0.1.7-rc.1", {includePrerelease:true})                               → false
satisfies("0.2.0-rc.1", "^0.1.1-rc.2 || ^0.1.5-rc.1 || ^0.1.7-rc.1", {includePrerelease:true}) → false
satisfies("0.2.0-rc.1", "… || ^0.2.0-rc.1", {includePrerelease:true})                          → true
```

**修法**：每个 `@deepseek-ai/dsh-*` peer 追加 `|| ^0.2.0-rc.1`（**保留旧的三条**，老运行时照样能装），并补上 `engines.dsh`（0.2.0-rc.1 新增的「作者声明的兼容范围」字段，与 peer 保持一致）和 `dsh.manifestVersion: 1`。测试里钉了一条**双向自校验**的守卫：先证明「0.2.0 之前的联合范围**必须不**接受 `0.2.0-rc.1`」（这正是当初的 bug），再要求 package.json 中每个 dsh peer 与 `engines.dsh` **同时接受四个运行时行**（`0.1.1-rc.2` / `0.1.5-rc.1` / `0.1.7-rc.1` / `0.2.0-rc.1`）—— 以后升版本忘了扩范围，冒烟测试会直接报出来，而不是等到界面上「插件不见了」。

**0.2.0-rc.1 没有改动的地方**（同一套扫描器 + 运行中实例的 slot 树核对）：`configForms.get(<条目 id>)` 的快照面仍是 `{status, value, writable, revision, …}`，仍要 `status: "ready"` 才有值；`plugins.item` 仍是**已声明**的 list slot，插件页仍按 `view: 'summary' | 'page'` 派发（只多了一个本卡片用不到的 `form` prop）；`conversation.input.model` 仍是 `single`（官方选择器在 `priority: 0`，本插件用 `-100` 抢座）；`modelDirectories` / `sessions` / `remote.session` / `slots` / `locale` 都在；宿主侧仍然只认「导出 `Config`」+ `.volatile()`（`volatileForm` / `isVolatilePath` 原样保留）。0.2.0-rc.1 **新增**的 `settings.plugins.tab`（设置 → 「内置插件」的标签页）**不是**本卡片的去处：那一节自称是「查看本部署**自带**的插件」的检视器，而 profile bundle 自己的设置页正是 `plugins.item` 的用途 —— 官方那四张配置卡（`agent-loop` / `shell` / `subagent` / `web-search`）在 0.2.0-rc.1 里也仍然注册在 `plugins.item`。

**一处必须跟着改的客户端行为**：0.2.0-rc.1 的 `slots.inject` **不再吞掉**回调里的异常 —— 回调抛错会被 `queueMicrotask` **重新抛出**，也就是变成**页面级未捕获错误**（0.1.7 只打一行日志）；同时 `slots.register` 本身变成了硬错误（slot 未声明、或同一 cell 同一优先级重复注册，都会抛）。所以「设置卡片」的注册现在包在 try/catch 里：失败只丢这张卡片并 `console.error` 上报，输入框那条座位不受影响（座位注册本来就是隔离的）。测试用一个「注册必抛」的 mock 把它钉住：`apply` 不许抛、座位仍要在、而且**必须**有上报 —— 静默吞掉也算失败。

**升级后怎么恢复**：bundle 层是**启动时组合**的，改完 package.json **必须重启 DSH**（刷新页面不够）。重启后本插件会在「插件」页出现，卡片与输入框滑块一起回来；若仍然不见，去看启动日志里有没有 `skipping profile bundle "@magiczerowxy/dsh-modef"` —— 那就是闸门还在拒它。

### 0.1.7-rc.1 的三处契约改动

该版本改了三处插件契约，旧写法会让插件**整个不激活**（fiber 停在 `pending (waiting for service: …)`，界面上什么都不出现，也不报错）。三处改动：

| 用途 | 0.1.5-rc.2（旧） | 0.1.7-rc.1（新） |
| --- | --- | --- |
| 读取/写入本插件的设置 | 注入服务 `settingsScope`，用 `ctx.settingsScope.bind({ namespace })` | 注入 **`configForms`**，用 `ctx.configForms.get("dsh-modef")`（参数是**宿主 profile 条目 id**，不是命名空间字符串） |
| 设置卡片挂在哪个 slot | `settings.plugin.item`，用 `key: <命名空间>` 定位 | **`plugins.item`**，用 `id` + `order` + `label`，且是**两形态**条目 |
| 宿主侧如何声明设置 | `ctx.settings.register(ns, Config)` + `settingsNamespace()` | **只导出 `Config`**（schemastery），由 loader 从 `fiber.runtime.Config` 读取 |

判据是把同一扫描器跑在**新旧两棵 `@deepseek-ai` 树上**（旧 717 个 js 文件 / 新 923 个）：`settingsScope` 在旧树命中 10 个文件、在新树 **0 个**；`settings.plugin.item` 旧 2 个、新 **0 个**；而 `modelDirectories`、`conversation.input.model`、`remote.session`、`slots`、`locale` **两版都在**，因此这几处未改动。同一个坑在启动日志里对别的插件是可查的：

```
web boot: 3 entries did not activate
@deepseek-ai/dsh-client-ui-aqua:   pending (waiting for service: settingsScope)
dsh-balance-credits-usage:         pending (waiting for service: settingsScope)
dsh-space-grotesk:                 pending (waiting for service: settingsScope)
```

**卡片形态的变化**：`plugins.item` 由插件页**自己**渲染列表项、标题、图标与展开控件，并把 `view: 'summary' | 'page'` 传给条目 —— 折叠时取一行说明，展开时取表单本体。因此卡片**不再自带** `<li>`／标题栏／箭头／手风琴，也不再自己存「未保存」徽标（这些都归插件页）。自带的 `ChevronIcon` 与 7 条相关 CSS 随之删除。这与官方四个自带卡片（`agent-loop` / `shell` / `subagent` / `web-search`）的写法一致。

**依赖要求**：`@deepseek-ai/schemastery` **≥ 3.18.3**。可编辑字段必须标 `.volatile()`，而 `volatileForm(schema)` 对没有任何 volatile 字段的 schema 返回 `undefined`，随后 `settings.write()` 会以 `has no volatile fields` **拒绝整个命名空间** —— 卡片能显示、但永远存不下去。`.volatile()` 是 **3.18.3 才加入**的（3.18.2 的 `Schema.prototype` 上根本没有这个方法，宿主 half 会在加载时直接抛错），所以 peer 下限提到 `^3.18.3`。

**两个未在界面上的键**：`lastSeatError`（崩溃栈）由浏览器 half 写回同一份设置；`diag` 是**已废弃的历史键**（写入者已删除，见下节）。旧服务接受**未声明**的键，新服务会**逐路径校验**并拒绝未声明字段（`Config field "…" is not volatile`）——`lastSeatError` 的写入带 `.catch()`，失败会**静默**丢掉遥测，所以必须在 schema 里声明。两者都用 `.default(undefined)` 显式去掉类型默认值（`z.array()` 默认给 `[]`、`z.string()` 默认给 `""`），否则每个没崩过的 profile 都会被写进这两个键。`diag` 保留声明**只是为了**让已存有 `diag: [...]` 的 profile 继续通过校验（schemastery 会保留未声明键，所以删掉声明也不会清理掉那份数据）。

## 「正在刷新模型列表」闪烁是怎么修的

**症状**：模型选择器浮层里**每约 1.9 秒**闪出一次「正在刷新模型列表…」，而列表内容从未变过。

**根因是插件自己造成的反馈环**。它当时带着一段临时遥测（代码注释写着 "Removed once the root cause is confirmed"）：把状态变化攒进缓冲区，用 **1.5 秒定时器**写回自己的设置文档。而在 0.1.7-rc.1 里，这个写入会闭合一个环：

```
1.5s 定时器 → 写 dsh-modef 的 diag → Host 的 describe() 发现 entry.options.config 变了
  → emit "settings/document-updated"
  → ui-model-selection: $on("settings/document-updated", () => catalog.refresh())
  → catalog.load() 把 status 置为 "loading" → 浮层显示加载条
  → 控制件观察到状态变化 → 又记一条 diag → 回到第一步
```

**实测证据**（直接读 profile 里那条目的 `diag` 数组）：`status=loading` → `status=ready` 周期 **1930ms**（1.5s 定时器 + 写入往返），而每次都写着 `models=39 fails=0` —— 目录从未变化，每一轮都是纯噪声。这段遥测还**毁掉了自己的用途**：缓冲区上限 80 条，实际被 78 条自己的循环输出占满，启动阶段的诊断（`apply start` / `scope bound` / `seat claim` / `mount avail`）**一条不剩**。

**修复分两层**：

1. **治本——删掉定时写入。** 遥测整段移除（它自己就注明是临时的），`setInterval` 在整个模块里为 0。实测修复后 profile 文件 **45 秒零写入**（修复前每 1.9 秒一次）。
2. **治标——加载条按「有没有内容」显示，而不是按状态。** `status === "loading"` 并**不等于**「用户没东西可看」：DSH 在 `settings/document-updated`、`llm/adapters-updated`、凭据变更等事件上都会重载目录，每次重载都短暂翻转状态，而**上一份快照仍然完好**（`groups` 还有数据，只有 `status` 变了）。所以门控改成 `choices.length === 0 && state.current === null`：只有真没内容时才显示加载条，后台刷新就地更新行、菜单不再闪白。`aria-busy` 用同一个门控，避免无障碍状态与视觉不一致。

## 功能 Features

- **模型下拉菜单（两级 / 可按提供商展开）**：第一级按**模型名称**汇集，第二级选**提供商**；这个折叠行为由设置里的**「折叠模型供应商」开关**控制（**默认开启**；关闭即恢复改版前按提供商分组的扁平列表）
  - **开关语义**：开启 = 下面的两级行为；关闭 = **改版前的样式** —— 每个「提供商」一个分组标题、该提供商的每个模型各占一行，没有 `>` 图标、没有侧边浮层，`→` / `←` 也不再有任何作用（`Esc` 直接关菜单，因为只剩一级）。两种模式**共用同一套行标记**（`.dms-option` / 品牌槽 / 文案列 / 对勾）与同一个 `chooseModel` 入口，所以配色、品牌图标、记忆功能在两种模式下表现一致
  - **默认值不进设置文件**：开关默认开启，因此只有**关闭**这一次操作会写入 `collapseProviders: false`；再打开则**删除**该键（`unset`）—— 从不碰这个开关的用户，设置文档里不会多出这个字段
  - **列表能滚，但不画滚动条**：模型列表与二级提供商浮层**共用同一个滚动容器** `.dms-groups`，它也是全插件**唯一**的滚动容器 —— 只保留上下滚动，**右侧滑条不绘制**。`overflow-y:auto` **原样保留**：滚轮、触控板、触摸拖动、键盘，以及聚焦某一行时浏览器的自动滚入都不受影响，消失的只是轨道与滑块。顺带一个好处：内容保持完整 **240px** 宽度，不再为一条「行数多了才出现」的滚动条槽位付出约 10px。两种写法都写了：`scrollbar-width:none`（标准属性，Firefox 与 Chromium 121+）与 `.dms-groups::-webkit-scrollbar{display:none}`（桌面客户端内核实际认的那条）。用的是**伪元素的 `display:none`**，而不是容器的 `overflow:hidden` —— 后者会把「滚动」本身一起干掉
  - **长按拖动可以调整模型顺序**：在第一级（按名称汇集）列表里**长按一行 300ms**，该行**平滑悬浮**成一个**稍大的浮层**（抬升 + 轻微放大 + 阴影），跟随指针上下移动；**其余行自动流出空位**给落点让位；松手后浮层**平滑过渡**滑入该空位，顺序**持久化**，下次打开仍是这个顺序。作用范围**仅第一级**：第二级是「某个名称下的提供商」，其顺序由已记住的提供商决定，不属于「模型排序」的语义；关闭「折叠模型供应商」的**扁平模式也不支持**（那是按提供商分组的结构，谈不上行的先后）
    - **为什么必须是长按而不是直接拖**：行本身是 `<button>`，点击会选中模型；而列表又是滚动容器。直接拖会让"点击选择"和"滑动列表"同时失效。所以 `pointerdown` 只**武装**手势，满足两个条件才真的开始拖：按住满 **300ms**，且指针位移**不超过 8px**（超过即视为滚动，交给滚动，见下）
    - **8px 的滑动容差是防误触的关键**：手指在列表上滑动时天然会抖，没有容差的话「想滚动」会被判成「想拖拽」。超过 8px 就**取消**长按定时器并清除行的已武装态，滚动照常
    - **用 transform 位移，而不是重排 DOM**：拖拽期间**没有任何一行被重新排序**。被拖的行留在文档流里，用 `transform: translateY() scale(1.04)` 抬起并跟手；其余行也被 `transform` 移到"落位后该在的位置"。这样做有三个好处：DOM 不变 → 过渡动画有稳定的节点可依附；行保持自己的宽度与文字度量（真正 portal 到另一处的副本得把这一切重新量一遍）；**提交顺序时画面不会跳**——松手那一刻其余行已经站在新顺序的位置上了，重排只是让布局追上已经画出来的样子
    - **空位是"被拖行的整行高度"**：摘走一行正好腾出**它自己**的高度，落点又正好需要这么多空间，所以两侧被跨过的行各移动**被拖行的身高**（不是各自的）。`dmsRowShifts` 就是这条算式：向下拖时区间内的行上移一格，向上拖时下移一格，区间外一行不动；**被拖行自己的位移恒为 0**（它由指针带动，再算一次就会走双倍）
    - **两个"位置没变"的槽位必须零位移**：`slot == from` 与 `slot == from + 1` 说的都是原地，所以两者都返回全零——拖回原位不会留下任何痕迹
    - **测量在拖拽开始时做一次，且是"静止时"的坐标**：落点判定用的是每行**未被位移前**的 top/height。若改用实时 `getBoundingClientRect`，测到的就是被自己的位移推走后的位置——**判据会被自己的结果改变**，落点会在两个槽位之间来回跳。静止几何是不动参照系
    - **`dmsMoveKey` 里有一个必须的 off-by-one 修正**：插入位置是相对**移动前**的列表量的，而实现是「先摘出被拖的行再插入」——摘除会让它后面所有槽位前移一格，所以向下移动时插入下标要**减一**。少了这一步，向下拖一格会原地不动
    - **跟手的那一行不能有过渡**：拖动中该行必须**逐帧贴合**指针，`transform` 上若有过渡就会慢一帧、快速拖动还会拖影。所以抬起的行写作 **`.dms-option.dms-optionDragging{transition:none}`**——**两个类**是必需的：基础 `.dms-option` 规则带着邻居滑动用的 `transition:transform .18s`，它在样式表里**更靠后**且**特异性相同**，只用单类选择器时这条 `transition:none` 会被它**覆盖**，抬起的行就会一路动画着跟在指针后面（这个回归是真实浏览器读取 computed style 才发现的：表里每条声明单看都是对的，源码扫描不解析层叠）。落位阶段用同样两个类的 `.dms-optionSettling` 把过渡**重新打开**，正好压过上面那条 `none`
    - **落位要"先加类、强制刷样式、再写 transform"**：同一轮样式重算里既换 `transition` 又换 `transform`，按规范**不会**产生过渡（浏览器没有可插值的起始计算值）——所以先换类（移除 `.dms-optionDragging`、加上 `.dms-optionSettling`），读一次 `offsetHeight` **强制冲刷**，再把 transform 写上去。读那次布局属性不是多余的开销，它正是让过渡成立的那一步
    - **抬升在滑入途中就卸下，而不是落地后弹掉**：落位开始时**同步移除拖拽类**——阴影、抬升底色、10px 圆角、0.96 透明度随即改为按 `.dms-optionSettling` 的过渡**在滑入期间淡出**；落位写入的 transform **不带 scale**，`transition:transform` 会把位移与缩放**一起插值**，浮层是边滑边"消气"回到 1x 落地的。`z-index` 与 `pointer-events:none` 由 settle 规则自己接管，滑入中的行仍压在邻居之上且不可命中。`commit` 时类被 React 重算掉，那时一切样式已与常态一致——**衔接处没有任何跳变**。原地松手（落点未变）也走同一套消气：translate 不变、只有 scale 在过渡，直接提交会让行无过渡地瞬间拍平
    - **落位结束后才提交顺序**：松手先播 180ms 的滑入动画，动画结束才真正写入顺序；`dmsDragCancel`（唯一出口，取消/提交都走它）在同一轮同步任务里**清掉所有 transform** 并触发重排。两步之间不可能插入一次绘制，所以用户看到的始终是"已经站好"的状态，不会看到中间态
    - **落点线已移除**：早先版本画一条 2px 插入线，那时列表不动、线是唯一反馈；现在**空位本身就是反馈**，再画一条只是重复。而且那条线是按**实时**矩形定位的，在"每行都被 transform 位移"的设计下只会画到被推走的位置上，会漂
    - **顺序按名称存 `localStorage`，不按位置**：位置一有目录变化就失去意义（提供商是**增量加载**的，模型也会增删）。存储是名称数组，**不在其中的名称排在已列出的之后**、彼此保持目录原有相对顺序（靠 `Array.prototype.sort` 的稳定性），所以目录刷新不会打乱用户排好的部分；指向已消失名称的旧记录也不会破坏排序
    - **指针移动每帧只写一次**：`pointermove` 一秒可以报几百次，只有绘制前最后一次可见；位置记进 `ref` 并用 `requestAnimationFrame` 合并，且**只有落点槽位变化**时才触发一次重渲染。同时用 `setPointerCapture` 让指针移出行外也继续收到事件。拖动中会**阻止行的点击**（浏览器在松手后还会补一次 `click`，不拦截的话落位会顺带切换模型），但这个"吞掉一次点击"的标记在下一次手势开始时就清除，因此不会误吞后续的正常点击
    - **拖到浮层上下边缘时列表自动滚动**：目标行不在可视范围内时，把浮层拖到列表上/下边缘 **30px** 以内，列表就开始自己滚动：速度随深入边缘的程度**线性加快**，到边缘（或越过边缘——指针可以离开浮层）达到上限 **10px/帧**；**进区即动**（向上取整——四舍五入会把进区的前半段变成死区，贴边减速时完全不动）。滚动是**自续的 rAF 循环**而不是挂在 `pointermove` 上：指针贴住边缘不动时 `pointermove` 停止触发，而这恰恰是这个功能要服务的姿势。三个消费行偏移的地方（指针移动帧、自动滚动 tick、松手）用**同一条表达式** `pointerY - startY + (scrollDelta || 0)`——少一项，浮层就会在滚动时从指针底下溜走、松手时跳位；`scrollDelta` **写后回读**（容器的 `scrollTop` 会两端钳制，信请求值会错放落点）；落点槽位也从"静止时"的行坐标里**减去已滚动距离**。列表矮到容不下两个区时退化为**全速**（那时几乎没有可滚的余地，缓动没有意义）；落位动画期间 tick 跳过、`dmsDragCancel` 里停止循环——取消的拖拽不能留一个没人托管的循环继续滚
    - 存储读写与「按名称记住提供商」共用同一套**防御式** `localStorage`（只在浏览器里，且每次访问都 try/catch）：存储不可用只影响持久化，不会影响选择器本身
  - **可选提供商：设置 → 模型 里给每个提供商一个开关**（需求：「在DSH[设置]-[模型]内除了[DeepSeek账号]和[DeepSeek]两个模型提供商外，其余的模型提供商加一个滑块开关，控制当前提供商是否启用，这样我就不用删除提供商但还能保留提供商配置」）
    - **为什么是页面底部的面板，而不是挂在每张卡片上**：0.2.x 的「模型」页给每张提供商卡片留了扩展位 —— **键控** slot `settings.models.provider-card`，按 `entryKey = 该提供商的 settingsNs` 派发。键控 slot **一个 key 只允许一个条目，同优先级再注册一个会直接抛错**（`keyed slot "…" already has an entry for key "…"`），而本部署里这个位置**恰好被占住了最要紧的那些命名空间**：`dsh-better-reasoning-effort` 占着 `llm-pi-ai`（workbuddy / xiaomimimo / gemin / glm / clip / step 全在里面），官方那几张配置卡也各自占着自己的。也就是说「每张卡片一个开关」在这里不是拥挤，而是**结构上做不到**。所以开关落在**页面底部的 `settings.models.footer`**（「提供商行与新增控件之后的扩展区」，**列表** slot、id 自取不冲突）——这正是同类插件已经在用的位置（同一个 better-reasoning-effort 的滑块、qoder 的凭据卡片都在这里）。面板注册整体包在 try/catch 里：`slots.register` 对「未声明的 slot」和「同格重复注册」都是**硬错误**，而 0.2.0-rc.1 起 `slots.inject` 的回调抛错会从微任务里**重新抛出（变成全局未捕获错误）**，所以注册失败必须只赔上这个面板本身 —— 卡片与输入框座位照旧（有专门的测试与变异钉住这一点）。**在不声明这个 slot 的运行时上**，`slots.inject` 根本不会触发，插件只是少一个面板，**不会报错、也不影响其余功能**（本机验证的版本为 0.2.0-rc.1/rc.2；0.1.7-rc.1 保持兼容的方式见上一节 peer 范围）
    - **面板自己列出提供商，数据来自宿主目录**：列表取自 `remote.session.modelCatalog()`（宿主对「每个可路由 provider+model」的自述），**不是**选择器读的那个客户端目录。理由是硬的：那个目录**正是这些开关要过滤的东西**，用它来建开关列表会让被关掉的提供商**没地方再打开**（它已经从列表里消失了）。宿主目录不受本插件过滤影响，所以关掉的那家仍然在面板里等着被打开。每行一个**路由 id**、按目录顺序、**去重**、没有 id 的行跳过；显示名用目录给的，缺了才回退成 id。宿主宣布适配器变化（`llm/adapters-updated`）时**重新读一次**——那是页面开着时提供商集合唯一会变的时机；重读期间**保留上一批行**，刷新不该把面板闪空
    - **两个 DeepSeek 路由整行不出现**：`deepseek-official`（「DeepSeek」，来自 `@deepseek-ai/dsh-llm-deepseek-api-key`）与 `deepseek-account`（「DeepSeek账号」，来自 `@deepseek-ai/dsh-llm-deepseek-account`）在**构建行列表时就被滤掉** —— 是**缺席**，不是渲染一个禁用的开关：需求明确排除它们（账号那条是用户自己登录的、API-key 那条是 composer 的常备路由），而「渲染了却点不动」只会让人以为功能坏了。断言因此是「这两个名字一个都不在行里」）
    - **关掉的是「可见性」，不是配置**：开关只维护**一份被关掉的提供商路由 id 列表**，**从不碰提供商自己的 profile**。这正是需求的原话 ——「不用删除提供商但还能保留提供商配置」：官方那张卡片上的 `删除` 才是唯一会移除 profile 的操作（且不可逆），这个开关是它的**可逆的一半**，端点、模型清单、凭据引用原样躺着，打开开关立刻回来
    - **列表有两个家，而且先写「先生效」的那个**：主拷贝是**本机 localStorage**（键 `dsh-modef.disabled-providers.v1`，与「按名称记住提供商」「行顺序」同一套防御式存储），因为**开关必须在点下去的那一刻就生效** —— 而设置文档要等**宿主 half 重新加载并投影出 `disabledProviders`** 才接受写入。所以每次翻转的顺序是：**先写本机存储**（立即生效，设置文档只读、或部署跑着旧宿主 half 时照样能用），**再尽力把同一份列表镜像进设置文档**（`set`；清空时 `unset`，这样从没用过开关的 profile 不会多出 `disabledProviders: []`）。读取时**以文档为准、回退到本机存储**：字段一旦被宿主提供就由它领跑（profile 备份/换机器也带得走），在此之前由本机存储回答。镜像被拒**只记一行警告、不弹错** —— 开关其实已经生效了，报「保存失败」才是误导
    - **测试把两个家都钉住**：翻转后本机存储必须有这条 id、设置文档必须收到同一条 `set`；清空时必须**既 unset 文档、又把存储键删掉**（不留空壳）；**文档写入被拒时开关仍然生效**（mock 一个只读的 `configForms`，断言本机存储照样更新）；以及**只有本机存储、文档里根本没有这个字段**时，选择器照样隐藏该提供商 —— 这正是宿主还没重新加载那段时间的真实状态
    - **选择器里，被关掉的提供商整行消失**：过滤发生在**构建 `choices` 的那一刻**（`disabledProviders.has(group.id)`），而第一级汇集、第二级提供商面板、键盘导航**全都从 `choices` 长出来**，三处不可能各说各话。唯一的例外是**当前选中的那个模型**：它的提供商即使被关，那一行仍然留着 —— 输入框上写着它、菜单却显示不出来（或者干脆选不回去）才是真的坏；而**同一名称下的兄弟提供商照旧隐藏**，例外不会顺着名称扩散（测试把这三件事逐条钉住）
    - **菜单里悄悄消失，不留任何提示**：被关掉的提供商的模型直接从菜单里消失，**菜单底部不会多出任何一行提示**（第一版曾在滚动容器外加过一行「已隐藏 N 个提供商 · 设置 → 模型 可启用」，按要求已整个删掉：节点、CSS 类、两种语言的文案键一并删除，不留死代码）。这条由**缺席断言**钉住 —— 关掉 1 个与关掉 2 个这两种状态下，都断言菜单里既没有那个节点、也没有请求过那条文案键，而不只是断言「看起来没显示」
    - **边界要说清楚：这只影响本插件的选择器**。开关维护的是**本插件选择器的可见性**，不是 DSH 的路由：关掉一家后，**官方那个选择器（本插件的「高级 effort」开关关闭时用的那个）依旧会列出它的模型** —— 本插件没有、也不打算有「让某个提供商彻底不可路由」的权限（那属于宿主的提供商配置，官方卡片上的 `删除` 才是那种操作）。档位、模型、端点随时还在，这正是「不用删除提供商」的前提；如果连官方选择器也要一起不显示，那需要的是关掉提供商自己的配置，不是这个开关
    - **记忆不会把关掉的提供商「复活」，但靠的不是额外判断**：`dmsPreferredOption`（点第一级行时落到「上次为这个名称选的提供商」）**没有**再查一次名单，而且这是有意的 —— 被关掉的提供商的选项**根本不在 `nameGroup.options` 里**（`choices` 就没放它进去），所以记忆命中不了它，自然回退到「还开着的第一个」。唯一会被保留的例外是**当前选中的那个**，而它正是设置 `selectedAt` 的那个选项，于是点击走的是 `selectedAt` 分支（保持不动），压根到不了这个函数。第一版这里确实写过一次「再查一遍名单」，但它**永远不可达** —— 一个测试驱动不了的守卫比没有守卫更糟，所以删掉了；测试改为钉住**可观测的那条路径**：记忆指向被关的 provider 时，点击落在还开着的那家（并且同一份记忆在 provider 开着时照常生效，证明钉的是开关而不是记忆坏了）
  - **对勾是 SVG，不是 `✓` 字符**：原来用文本 `✓`（U+2713），字形自带**字体度量** —— 宽度与基线取决于客户端实际解析到的字体，所以对勾列（以及它右侧的 `>`）在不同机器上可能差一两像素；字体缺这个码位时还会渲染成方框。现在是一条 `path` 描边（`stroke:currentColor` 保留原来的品牌色、圆头圆角），**空状态不再用不换行空格占位**，而是由 `.dms-check` 固定 **14×14 盒子**保证列宽不随选中状态变化
  - **按名称汇集，不看 ID**：名称**完全相同**的模型合并成一行，**ID 相同与否不参与判断** —— 提供商 A 的 `deepseek-v4-pro` 与提供商 B 的 `deepseek-v4-pro-0813` 名字都是 `DeepSeek-V4-Pro`，合并为**一行**；而提供商 C 的 `Deepseek-v4-pro`（只差大小写）**单独成行**。判定就是原始 `name` 字符串的 `===`，**不做** trim、不做大小写折叠 ——「名字只要有差别就单独汇集」是需求本身，所以**显示名就是身份**。行的顺序沿用官方目录返回的提供商顺序
  - **`>` 图标**：放在**对勾右侧**（而不是紧贴名称），因此永远不会被误读成「已选中」标记。点箭头**不会**顺带选中模型（`stopPropagation` + `preventDefault`），只切换提供商浮层
  - **Step 模型全系都有品牌标**：品牌推导只看 **provider / 模型 ID 的段匹配**，StepFun 那一行原来被钉死成字面量 `step-3`，于是只有 `step-3.7-flash` 拿到标，本部署的 `step-5-preview` 直接落到**空槽** —— 两行并排、一行有标一行没有，而名字上完全看不出差别。现在写成 `[/stepfun|(^|[/._-])step-/]`：`^` 与 `[/._-]` 是**段边界**，所以 `step-5-preview`、`step-2-16k`、`step-1v-32k`、`step-r1-v-mini`，以及聚合路由里的真实拼写 `stepfun/step-3.5-flash` / `stepfun-ai/step-3.7-flash`（见部署自带的 `pi-ai` 目录）**全部命中**；而 `megastep-3`、`timestep-x9` 这种**只是包含 "step-"** 的别家模型**不会**被蹭上 StepFun 的标 —— 旧写法连这个都错（子串匹配会把 `megastep-3` 也标成 StepFun）。`stepfun` 是 `mono` 标（`currentColor`），所以同样由上一条的槽位淡化统一管理，不写任何厂商特判
  - **代号 ID 的网关靠「显示名」认领品牌**：品牌推导原本只看 **provider / 模型 ID 的段匹配**，但 ID 只对**发布它的适配器**有意义 —— `dsh-provider-qoder` 是**多厂商网关**，整条目录都用内部代号注册（`qmodel_38max` / `qfmodel` / `dmodel` / `dfmodel` / `gmodel` / `gfmodel` / `kmodel_latest` / `kmodel`），于是这**八条路由全部落到空槽**，而它们旁边的文字明明写着「Qwen3.8 Max」「DeepSeek V4 Pro」「GLM 5.3」「Kimi K3」。本部署第一级共 **19 个名称、17 条有标**，其中**只由 qoder 一家承载的 Qwen3.8 Max / Qwen3.8 Flash 就是那两条空白槽** —— 空白行紧挨着有标的兄弟行，名字上看不出任何差别（需求：「为模型选择器中的没有图标的模型加上图标」）。现在**显示名也参与推导**，层级顺序固定为 **模型 ID → 显示名 → provider（其文本 → 其表）**：ID 最具体、provider 最不具体，所以**更具体的一方永远赢**（`claude-opus-4-6-thinking` 挂在 Gemini 代理路由上仍然是 Claude，改动前后一致），而 **provider 级条目绝不能压过显示名** —— 一个网关同时代理好几家的模型，把它的路由 id 映射成一个 logo 就等于给旗下每一行都盖上那个 logo（这也是 `DMI_PROVIDER_BRANDS` 里**故意没有** `qoder` 条目的原因；它的代号 ID 同样**故意不进** `DMI_MODEL_PATTERNS`：给一家网关的私有代号写规则既脆弱、又只服务一家）。显示名本来就是**第一级汇集的身份**，对这类网关它是唯一还活着的身份信号。四处调用点（第一级行、扁平模式行、对话框触发器、胶囊标题行）统一走 `dmiBrandOf(group, model)` —— **少传一个名字就又会画出空白槽**，所以测试直接**表驱动跑通本部署真实的 33 条路由**（含 8 条 qoder 代号路由，逐条断言品牌，并断言图标表里确实有该键的**画**），把「任何一处 `dmiBrandFor(...)` 都不许两参调用」钉成结构断言，再用四条行为断言（第一级 / 扁平模式 / 触发器 / 胶囊标题）确认代号路由在**真实渲染路径**上也拿到了标
  - **选中行图标正常，未选中行图标淡化**：`.dms-optionIcon{opacity:.6}` + `.dms-optionSelected .dms-optionIcon{opacity:1}`（0.15s 过渡，选中态移动时是渐变而非跳变）。**为什么必须加在槽位而不是图标本身**：列表里混着**两类**标记 —— `mono` 类用 `fill:currentColor` 绘制，而品牌类（DeepSeek / 智谱 / Qwen / Claude / Gemini …）自带**硬编码填充色**；而行文字色**不随选中变化**（选中只换背景），所以两类都不会自己响应选中态，每一行的图标都保持全强度，选中行的图标得和所有其他行争抢注意力（实测：WorkBuddy 的行显示的是 `deepseek-v4.1-flash` 匹配到的**深蓝鲸鱼标**，硬编码色，永远鲜亮）。淡化**槽位**用一条声明就统一了两类；而把条件挂在行自身的 `dms-optionSelected` 上，规则讲的是**行的选中态**、不是某个厂商，所以每个提供商（含 WorkBuddy）行为完全一致。像素实测：自带色标记与 mono 标记未选中时都衰减到 **0.608 / 0.605**（选中为 1）——两类一致，无厂商特判
  - **图标的光学基线按调用点各自设定**：`DmiBrandIcon` 的垂直微调 `dy` 是**每个调用点传参**（和 `size` 一样），因为四处各自处在一个不同的行盒里。**共享默认 0.8px**（`props.dy` 缺省时用它），三处沿用：浮层标题行的当前模型名（18px）、两级列表的行图标（16px，按名称汇集与扁平模式**各一处、都是独立调用点**）。**唯一覆盖的是对话框里的模型选择器**（14px，唯一放在 28px flex 按钮里而不是堆叠文字行中的标记），它被**独立调整过两次**，两次都是**相对于该处自己当时的值**、与共享的 `0.8` 无关：

    | 值 | 来源需求 | 算式 |
    | --- | --- | --- |
    | `-0.7` | 最初的手调值 | — |
    | `1.3` | 「对话框中的模型加载器的图标下移2px」 | `-0.7 + 2` |
    | **`0.3`** | 「把对话框中的模型选择器左边的SVG图标上移动1px」 | `1.3 - 1` |

    CSS 的 **`+y` 是向下**，所以「下移」是**加**、「上移」是**减**。**每一步都必须从该处的前一个值出发**：写成 `共享值 ± n` 会把这个标记悄悄锚到一个它从未有过的位置（这个错误在测试里真实发生过一次）。像素实测（首次下移）：同一按钮内字形顶边 **9px → 11px**，即**恰好 2px**，字形高度不变（9 行），确认是纯位移而非缩放。测试按上表**逐步推导**期望值，并校验相邻两步首尾相接，所以新增一次微调只需在表尾追加一行
  - **每一行都有 `>`，包括只有一个提供商的名称**：单提供商的行点开浮层就显示**那一条**（提供商名 + 副行 + 对勾 + 倍率照常）。这样**行的形状不随提供商数量变化** —— 想打开就点，不需要先看清这行有几个提供商；ARIA 也是统一的：每行都带 `aria-haspopup="menu"` 与跟随开合状态的 `aria-expanded`。`→` 键同理，单提供商的行也能进入它自己的浮层（键盘路径不比鼠标路径窄）
  - **`>` 的点击区域比它看起来大**：可见方框仍是 **18×18**（外观一点没变），但外面套了一圈**不参与布局**的 `::after` 隐形环（四边各外扩 6px），**实际命中区 30×30**。因为是伪元素、命中测试会落到它所属的那个 span 上，所以点击处理器、`:hover` 高亮、`:focus-visible` 焦点环和 `cursor:pointer` 全部照旧生效 —— 只是「能点中」的范围变大了。**6px 这个数是被它所在的行约束出来的**：行高 34px（20px 行高 + 上下各 7px 内边距）、右侧另有 8px 内边距，所以 30px 的环**始终落在行的盒子内部** —— 一旦溢出到行外，就会开始抢上下相邻行的点击；横向溢出则会让滚动容器（`overflow-y` 会把另一轴也算成 `auto`）多出一个横向滚动
  - **WorkBuddy AI 的副行改用模型 ID**：本部署给这个厂商的**两个不同模型**（`deepseek-v4.1-flash` 与 `deepseek-v4.1-flash-sg`）配了**同一个显示名**「DeepSeek V4.1 Flash」，于是它们必然被第一级汇集成**一行**（这正是按名称汇集的设计行为），而它背后的提供商浮层就会列出**两条文字完全相同**的行 —— 无法选择。ID 是唯一不同的文字，所以对这类提供商，第二级的**副行显示 ID**（主行的提供商名、第一级列表、以及**其他所有提供商**都不受影响，仍然显示名称）
    - 匹配方式是**大小写不敏感的子串**，**provider id 或显示名任一命中即可**。之所以故意这么宽：同一部署里 `workbuddy-ai` 与 `workbuddy` 是**两个独立的提供商行**，且它们的 id 与显示名拼写并不一致（`workbuddy-ai` vs `WorkBuddy AI`）—— 只按 id 匹配会漏掉第二个，只按显示名匹配会漏掉第一个
    - 例外清单就是代码里的 `DMI_ID_LABEL_PROVIDERS = ["workbuddy"]`；要再加一个厂商，往这个数组里加一个词即可
    - **副行同时带倍率**：这个厂商把 credits 倍率**拼在模型名尾部**（`dsh-workbuddy-connect` 的 `RATE_SEPARATOR`，即 SPACE + U+00B7 + SPACE，形如 ` · x6.67`；上游的 `x0.79 credits` 会被 `normalizeCredits` 去掉 `credits` 单位词，所以显示成语言中性的裸倍率）。因此副行是「**ID + 倍率**」，例如 `gpt-6-astra · x6.67` —— 名字原本承担的信息（倍率）没有因为改用 ID 而丢掉
      - **两个来源，按可靠性排序**：① **交付名自带的尾巴**（免费、必得，但用户设过 `modelNames` 改名的模型**没有**这个尾巴 —— 覆盖名会连同倍率一起被替换掉）；② **provider 自己的同源只读状态路由**（`/plugins/dsh-workbuddy-connect/ai/status` 与 `/plugins/dsh-workbuddy-connect/status`），它**对每个模型**都返回 `credits`，改名与否都有
      - **路由按「覆盖度」匹配，绝不按模型 id 合并**：两条路由是**按变体**（国际 / 国内）划分的，而两个变体对**同一个模型 id 的倍率并不一致**（例：`deepseek-v4.1-flash` 在国际端点 `x0.00`、在国内端点 `x0.03`）。所以对一个 provider，选取「命中其模型 id 最多」的那张表；把两张表合并成一个「按 id 查」的映射会取到错误的倍率
      - **网络行为收敛**：只在**打开一个确实含有该 provider 的菜单**时才请求（别的菜单完全不碰网络），**每页至多一次**，两条路由**各自独立结算**、全部返回后才发布（一条缺失不会取消另一条）；失败/缺字段一律安静降级到来源 ①，再不济就是**裸 ID**，绝不抛错、绝不让选择器崩
  - **第二级浮层**：列出该名称下的**所有提供商**，每行**主行是提供商名、副行重复模型名** —— 这正是「同名不同提供商」的两行得以区分的地方（上一条的例外除外）。默认贴在菜单**右侧**；右侧放不下时**自动翻到左侧**（保证浮层完整可见），纵向对齐菜单顶部、底部放不下则改为底对齐。位置由 JS 量测后以**内联样式**下发（`left` / `top` / `max-height`）；**拿不到量测时**（菜单隐藏、或宿主没有 `getBoundingClientRect`）回退到 CSS 的 `left:calc(100% + 8px)` 兜底，**绝不猜一个锚点**
  - **点击第一级行的直接语义**：若该名称下**已是当前选中的**提供商，就保持它（等同于关闭菜单，不会跳到别的提供商）；否则取**上次为这个名称选的**提供商（见下一条），只有在**没有记忆**或**那个提供商已不在目录里**时才回退到目录里的第一个。要精确挑提供商就用 `>`
  - **记住每个名称上次选的提供商**：用 `>` 选了某个提供商之后，下次再点这个名称的行会**直接回到那个提供商**，不再每次都从默认（目录里第一个）开始。记忆的**键是第一级身份（模型名称）** —— 因为那是用户在第一级实际选的东西；值是该次选择的 `provider id + model id`。写入时机是**用户点下去的那一刻**（而不是等宿主确认）：记忆记录的是「用户选了什么」，一次缓慢或被拒绝的选择不该让它悄悄改指别家，而重复记同一个提供商本身无害
    - **存哪里**：浏览器自己的 `localStorage`（键 `dsh-modef.provider-memory.v1`），**刻意不写进 DSH 的 settings 文档** —— 这只是本机的一个 UI 便利，走 `settingsScope` 就意味着**每点一次提供商都要写一次设置文件**。因此它也**不受**插件设置开关影响；卸载插件后残留的只是这一个键
    - **存储被当成不可信**：`localStorage` 在受限 / 隐私模式下可能**读取时就抛异常**（不只是写入），旧版本留下的值也可能根本不是 JSON —— 所以每处访问都有保护：读不出来当空、写不进去只损失持久化，**绝不会让选择器崩掉**。没有可用存储时，页内缓存仍然记得（seat 卸载重挂也在，页面刷新才丢）
    - **容量有界**：最多 100 条，超出按**最近最少使用**淘汰（重复选择会把该键移到末尾，所以淘汰的是「最久没再选过」的那个）
    - **失效即回退**：记忆里的 `provider + model` 必须**在当前目录里仍然存在**才会被采用 —— 提供商下架、模型改名都会自动回到目录里的第一个，而不是选不动
  - **键盘**：`↑` / `↓` 在第一级内移动（浮层打开时也不会跳进浮层）；`→` 为当前聚焦的行打开提供商浮层，`←` 收起浮层；`Esc` **逐级退出** —— 先关浮层、菜单留在原地，再按一次才关菜单
  - **浮层打开的是「名称」而不是「第几行」**：`subOpen` 存的是名称键。官方目录的提供商是**增量加载**的（所以才有分组加载失败的提示），新分组可能插到已展开那一行**前面**；若用下标记录，浮层会悄悄换成另一个名称的内容
- **对话框上的模型名完整显示**：输入框里的模型选择器显示**完整模型名**，不再被省略号截断。宽度上限取自 DSH **自带的**那个选择器（`@deepseek-ai/dsh-client-ui-model-selection`）：`max-width:min(360px,45cqw)`；`45cqw` 相对的是输入框那一行 —— 该行自己声明了 `container-type:inline-size`，所以上限会**随输入框宽度缩放**。原来这里写的是**固定 180px**，即官方预算的**一半**：扣掉品牌图标 14px（另有 1px 左 / 2px 右外边距）、内边距 12px、两个 4px 间隙、箭头 14px 之后，名字只剩 **129px**。实测在 736px 宽的输入框里，官方模型目录中有 **5 个真实模型名**放不下，最长的 `DeepSeek V4 Flash Vision Exp` 需要 **176px** —— 官方选择器能完整显示，这个插件却把它们截掉了。改后同一行的上限解析为 **324px**、名字预算 **273px**，实测 **38 个真实模型名全部完整显示（0 个截断）**；同一场景下整行不溢出（trailing 307.63px / 行 736px，行高仍是一行 42px）。省略号**保留**作为最后兜底：万一名字真超过上限，它会在按钮**内部**截断，而不是把文字溢出到按钮外面
- **推理强度滑块**：档位来自模型 `reasoning` 配置（如 Off / High / Max），拖拽/点击/键盘均可调节，松手平滑吸附
  - **每个模型记住自己最后的档位**（需求：「给模型选择器中选择的模型记住他最后的模型强度」）：把 DeepSeek V4.1 Flash 调到 Max，切到 GLM 5.3 调到 Low，再切回 Flash 仍是 **Max**，切回 GLM 仍是 **Low** —— 而不是所有模型共用一份全局档位
    - **键是「路由」，不是「模型名」**：存的是 `provider id + model id`（键 `dsh-modef.effort-memory.v1`，与按名称记提供商的 `provider-memory.v1` **是两个独立的键**，刻意不合并）。理由是硬的：**档位只在某个具体模型的 `reasoning.efforts` 列表里才有意义**，而两个提供商可以共用同一个显示名却给出不同的档位表（本部署的 `deepseek-v4.1-flash` 与 `deepseek-v4.1-flash-sg` 就同名）。若按名称记，A 家的 Max 会被端给 B 家 —— 而 B 家可能根本没有 Max 这一档。按名称的那个记忆回答的是「这个名字我想要哪家」，两者语义不同，绝不能互相借用
    - **值是档位 ID（`low` / `high` / `max`），不是下标**：下标在模型档位表一变就失去意义，而目录**确实会变**（提供商增量加载、模型增删）。测试对键的组成有直接断言：去掉 provider 或去掉 model id 都会失败
    - **恢复时必须对着目标模型自己的档位表校验**：`dmsEffortRestore` 只在「记住的那一档仍在该模型的 `reasoning.efforts` 里」时才交还，否则返回 `null` 让宿主的 `defaultEffort` 接管。提供商重发一个更短的档位表时，旧 ID 既不会被发出去、也不会选中一个该模型无法表达的档位。模型完全**没有** `reasoning` 块时列表为空，自然没有恢复 —— 与滑块自身「不渲染推理控件」的姿态一致
    - **恢复跟着「换模型的那一次 `select`」一起走**：`select(selection)` 本来就接受可选的 `reasoningEffort`（宿主目录的既有契约，官方选择器也是这么传的），所以恢复的档位**和模型变更在同一个请求里**。若拆成两次调用，会出现两次 `status:"selecting"`、两次宿主往返，以及**中途先闪一下模型默认档位**再到记忆档位的可见跳变
    - **记录时机是「用户按下档位的那一刻」**，与上面按名称记提供商同样的纪律（不等宿主确认）：用户选了什么就记什么，一次缓慢或失败的 `select` 不该让记忆悄悄改指别处，而重复记同一档位无害。**只有真正的档位变化**才会写：`commitEffort` 对「已经是这一档」提前返回，所以重开浮层、或提交当前档位，都不会重写记录
    - **存储同样被当成不可信**：与其它三处共用同一套防御式 `localStorage` —— 受限 / 隐私模式下**读取本身就抛异常**、旧版本留下的值可能不是 JSON，一律「读不出来当没有、写不进去只损失持久化」，**绝不让选择器崩掉**；完全没有存储时页内缓存照常工作，只是刷新后丢。容量上限 100 条，超出按**最近最少使用**淘汰
    - **不新增任何设置项、也不写 settings 文档**：这是本机的 UI 便利，写设置文档等于每调一次档位就写一次文件；卸载插件后残留的只是这一个 `localStorage` 键
  - **没有推理档位的模型，不显示推理控件**（需求：「滑块栏去掉'Default'这个挡位」）：滑块曾会在模型**没声明 `defaultEffort`** 时补一个合成档位 `Default`，但它**什么都选不中**（写入选择时会被跳过），只是让滑块看起来有挡位。现在**只使用模型真实声明的档位**：`reasoning.efforts` 为空或缺失时，档位列表为空，整个推理控件（头部档位文字、滑块、浮层）都不渲染 —— 与「模型完全没有 `reasoning` 配置」时的姿态**完全一致**。有真实档位的模型不受影响，档位名永远是真实档位名
- **最高档动画样式**：
  - **喷射流光 (spray-flow)**：蓝紫渐变流光 + 火箭喷射粒子，粒子从喷口逐步点火喷出
  - **暗流涌动 (undertow)**：白→紫渐变点阵 + 亮点从右端喷射向左涌动、逐渐消散；进出最高档有对称的揭示/收起动画
  - **流体 (cosmos)**：**浅色流体，每次打开浮层随机重掷**——近白浅蓝底上漂浮着淡蓝 / 中蓝 / 深蓝三层柔边"墨团"，边缘由 `filter:blur()` 化成云絮状，**无闪点、无光斑、无条纹**。**每次打开推理强度浮层，整套效果由 JS 重新发牌**：底色与每团墨的颜色（蓝色家族分段范围内）、墨团数量/尺寸/位置、每层的游荡路径（4–6 个随机 `translate+scale` 关键帧、0% 与 100% 完全一致的闭环）、时长（基础 14–22s / 中层 9–16s / 顶层 5.5–11s 且强制两两相差 ≥1.5s）、**运动方向（normal / reverse）与初始相位（负延迟）**全部随机——颜色搭配、运动方向和速度每次都不固定。重掷发生在 `openEffort()` 里、面板绘制之前；keyframes 名带本次序号后缀，换掉专属 `<style>` 元素的文本即让运行中的动画即刻按新牌重绑（无需 React 重挂载）。静态样式表里的同构规则只是**回退**（无 DOM 时效果仍在）。不变量始终成立：墨团纵向半径 ≥ 3× 杆高、中心统一 50%（**不分上中下**）、左右外扩 25% + `overflow:hidden`（不露边）、`ease-in-out` 胀落（无 `linear` 行军）、**无一次性入场动画**（只由 `.dms-fillCosmos` 自身的 0.5s 透明度揭示，进出最高档完全对称）
  - **晚霞 (sunset)**：**配色直接采自参考图，每次打开浮层随机重掷**。三层结构 —— `.dms-sunsetSky`（天空底色）、`.dms-sunsetCloudLo` / `.dms-sunsetCloudHi`（云雾与受光云顶）、`.dms-sunsetGlow`（光线）。
    - **色板来自图片本身，不是凭印象配的**：对参考图做 median-cut 量化，取到四族颜色 —— **长春花蓝 `#8fa5f6` / `#7982d7`**、**紫罗兰 `#7472a3` / `#695d6d`**、**玫瑰褐 `#92747d` / `#a78292` / `#c68473`**、**金橙 `#eea76b` / `#fdc96c` / `#fbde97` / `#fdf1a5`**。代码里这 11 个色值就是那份采样结果（`SUNSET_PALETTE`），发牌时只做两件事：天空底色对族内色值做小幅抖动，云雾 / 光线取**相邻两族的混色**。因此「以图片色调为主」是**构造性保证**，而不是碰巧配得像。
    - **天空是分层的（这与「流体」刻意相反）**：晚霞本来就是上蓝下金，所以底色是**九段竖直渐变**，按图片自身的上下顺序排列。发牌时每个色标在**自己所属的族**内抖动、位置也各自移动（单调递增、首 0% 末 100% 固定），所以地平线高低每次不同。
    - **九段渐变必须配模糊**：杆高只有 24–28px，九段渐变平均每段约 **3px** —— 不处理的话会渲染成一条条**硬边色带**（正是「流体」被测试钉死不许出现的观感）。所以天空层带 `filter:blur(4px)` 把色带融成连续天空。**模糊必须与"向外扩边"成对出现**：滤镜靠采样**盒子外**的像素来模糊，若仍是 `inset:0`，盒外采样到的是透明，边缘会淡出并**露出底下深色填充**形成一圈暗边。因此天空层四边各外扩 6px（`overflow:hidden` 负责裁剪，外扩不可见）。测试把这两半**一起**断言 —— 只加模糊会露暗边，只外扩不模糊仍然是色带，任一单独存在都是缺陷。
    - **云雾不是满高色带**：墨团是径向色块，但**纵向中心自由**（30–72%）、**纵向半径只有 20–44px**（远小于杆高），所以读起来是"有厚度的云"，而不是「流体」那种贯穿全高的横向色带。发牌时墨团数量（2–3）、尺寸、横向位置、纵向深度、浓淡全部随机。
    - **光线会"呼吸"**：`.dms-sunsetGlow` 的关键帧**同时动画 `transform` 与 `opacity`**，所以光线的**强度**在变化，而不只是整块天空从下面滑过 —— 这就是「光线色调的不规则变化」。三层各自有**互不相同**的闭环游荡路径、时长（基础 15–23s / 受光云顶 10–17s / 光线 6–12s，且强制两两相差 ≥1.5s）、方向与初始相位，三者叠加永不重复。
    - 静态样式表里的同构规则只是**回退**（无 DOM 时效果仍在）。重掷同样发生在 `openEffort()` 里、面板绘制之前，专属 `<style>` 元素为 `@magiczerowxy/dsh-modef/sunset.css`。
    - **减弱动效也覆盖随机发牌**（这一条同时修好了「流体」的既有缺陷）：发牌产生的 `<style>` 排在静态样式表**之后**，而 `@media` 查询**不增加特异性** —— 同特异性下后者胜出，所以静态表里那句「减弱动效时 `animation:none`」会被每轮的动画规则**反超**，用户开了减弱动效也照样看到三层在动。修法是**每一轮发牌自带冻结条款**，并排在该轮动画规则**之后**（同一张表内、顺序在后，必然胜出）。测试对两个样式的每一轮都断言「冻结存在」且「位置在动画规则之后」。
- **样式「彩虹猫」已删除**（需求：「删除『彩虹猫』样式」）：下拉里不再有它，像素猫手柄、彩虹拖尾、专属 keyframes 与全部 `.dms-*nyan*` / `.dms-rainbow*` 规则**一并删干净**，不留死代码。
  - **旧 profile 里的 `effortStyle: "nyancat"` 会自动回落**：样式的合法值由白名单（`EFFECT_STYLES.some`）判定，认不出来就取默认 `spray-flow` —— 选择器与设置卡片读的是同一份白名单，所以两处同时回落。**不做数据迁移、也不写坏配置**：文档里那个已失效的值原样留着，用户下次点保存时自然被覆盖。
  - 这条边界由测试钉住：一个 `effortStyle: "nyancat"` 的 profile 渲染时**不得出现任何已删类名**，且最高档必须带上默认样式自己的运行时标记（`dms-fx-spray-flow`）—— 只断言「没渲染出猫」是不够的，那样连「回落到默认」都验证不到。
- **滑块栏形状**：两种形状**完全独立**，各自的视觉互不影响
  - **圆角矩形**（默认）：圆角轨道（10px）、白底圆角矩形手柄（9px 圆角，带 ↕ 图标）、顶部左对齐「推理强度 + 档位」文字、滑块两侧 Faster / Smarter 标签、浮层圆角 17px
  - **胶囊**：顶部为**居中**的一组「`Effort` 标签 + 档位小胶囊」，标签在上、胶囊在下（如 `Effort` / `Max`）；档位小胶囊为**磨砂玻璃**质感（哑光：20px 背景模糊 + 均匀半透明玻璃体 + 柔和漫射边，**无镜面高光、无增艳**，只有极轻的外阴影）；当「浮层毛玻璃效果」开启时，该行**不再自己上色也不再叠模糊**，透明度与浮层完全一致（避免嵌套 backdrop-filter 把这一行渲染成更实的色块）；轨道与内条都变成长条胶囊（左右两端为完整半圆）；未达档位的部分用 `--dms-well` 变量（毛玻璃下同步变为半透明），因此内条是嵌在同一枚胶囊里，而不是"白框里嵌一条灰槽"；**只有一层胶囊、不描边**——仅靠**四周均匀**的柔和阴影体现轮廓（零偏移，不下沉）；内条右端半圆与手柄**同心**，即内条会多延伸一个半圆半径把小白圆包在右端（最高档时内条正好铺满整条轨道），手柄是 20px 小白圆、四周留 4px 内条色圆环；端点标签移除；浮层圆角 21px 以呼应全圆的杆端
    - **外围那层大胶囊已移除**（"把滑块栏胶囊外围的那一层大胶囊去掉，只保留内层胶囊"）：杆上原先还有一条 `box-shadow: 0 0 0 4px var(--dms-well)` 的**扩散圈**，用同样的白在杆外又画了一枚大 4px 的胶囊，把两侧阴影**推离**杆体（像素剖面可见：旧版在杆顶外 −4px 处亮度跳回纯白 255 形成断层，新版从 −5px 平滑递减 247→244→240→232，阴影紧贴杆缘）。它已删除。要区分的是：`0 0 0 <spread>`（**四个长度** = 扩散圈，画出更大一圈轮廓）已禁止；`0 0 3px`（**三个长度** = 纯模糊，只柔化杆自身的边缘）仍然允许——守卫按长度个数判别，不会误伤正常的阴影微调。

- **档位渐变文字（两级）**：全档文字载体 —— 小胶囊里的档位文字、圆角矩形头部的档位文字、以及对话框（组合输入框）上的「推理强度 + 档位」—— **按档位分两级着色**：

  - **最高档之前的一档（High）**：`.dms-labelGradHigh`，**淡蓝 → 蓝**流动渐变，色标 `#7DD3FC → #38BDF8 → #2563EB`，4.5s 循环（周期刻意与最高档不同，两级同时出现时不会同步得像同一块）。更低的档位保持纯色。
  - 两者的取舍是**层级**：低档必须**更淡**（平均亮度 152 vs 116）、**更偏青蓝**（蓝红差 172 vs 129），且低档**每一个色标都必须是「蓝 > 绿 > 红」的青蓝**、绝不能在中途转紫；而最高档的色带**红通道必须递增**（蓝→紫的旅程）。测试把这两条**色系形状**断言都钉住了 —— 只比"谁更亮/更蓝"是不够的：把最高档的色带原样搬给低档时，那两条关系**恰好也成立**（亮度只差 0.4），实测就是这么漏过去的。
  > **色标为什么从「白紫」改成了「蓝紫」**：原来的色标是 `#e9d5ff → #c4b5fd → #a855f7 → #7c3aed`，**第一个色标 `#e9d5ff` 是近乎白的淡紫**（rgb 233,213,255，彩度仅 **42**）。因为 `background-size:200%` 让元素静止时只显示渐变的**前半段**，那一端就主导了整段文字 —— 于是读起来是「白 → 紫」而不是「蓝 → 紫」。现在每个色标都落在饱和区间（彩度 187 / 142 / 154 / 162），**整个动画周期内最低彩度 140**，任何时刻都不会褪成白色；并且与喷射流光内条的渐变（`#4F46E5` / `#7C3AED` / `#A855F7`）及浮层蓝色主色（`#3b82f6`）同族，文字与它所在的那条栏是同一色系。实测彩度：旧色标 116 / 117（发白），新色标 **183 / 186 / 183**（小胶囊 / 对话框 / 圆角矩形），纯蓝对照 187。「淡蓝」这一级用同样的尺子量过：彩度 128 / 192 / 202，**整个周期最低 128**，所以它读起来是淡蓝而**不是白**。
  > **流动曾经根本不存在（已修的根因缺陷）**：两条渐变规则都写着 `animation:dms-textflow 3.5s …`，但**整个插件里从未定义过 `dms-textflow` 关键帧**。浏览器遇到**无法解析的动画名会静默丢弃**整条动画 —— 不报错、不警告、屏幕上也看不出「本该在动」，所以自这套渐变加入以来，它其实一直是**静态渐变**。现在补上了关键帧（`0% → 50% → 100%` 走 `background-position:0% → 100% → 0%`，**闭环**所以循环处不跳变），并把「关键帧必须存在」写成了**根因断言**：另加「色带宽度必须 >100%」（否则没有可滑动的余量）与「至少要有一个非零位移」（否则动画在动、视觉没动）。
  > **一个已修的隐患（根因 + 兜底两层）**：`.dms-pillValue` / `.dms-panelValue` / `.dms-effortCaption` 原本用**普通单类选择器**声明 `color`，位置在 `.dms-labelGrad` **之后**且特异性相同，于是会**盖掉**渐变里的 `color:transparent` —— 渐变只剩带前缀的 `-webkit-text-fill-color:transparent` 一根独苗在维持透明。这一条一旦失效（被主题覆盖，或被打包/服务端转换丢掉 `-webkit-` 前缀属性），小胶囊、圆角矩形档位文字就会**静默退回纯蓝**、渐变整个消失。
  >
  > 现在做了两层：**① 根因**：把纯色改成 `:not(…):not(…)` 门控（`.dms-pillValue:not(.dms-labelGrad):not(.dms-labelGradHigh){color:#3b82f6}`、`.dms-effortCaption` 同理），渐变档位时压根不存在与之竞争的 `color`，透明度由**普通 `color` 属性**给出，完全不依赖前缀属性；**② 兜底**：再用双类选择器 `…​.dms-labelGrad` / `…​.dms-labelGradHigh` 按特异性钉死。
  >
  > **这条链式排除是必须的，不是风格问题**：`:not()` 会把**参数的选择器特异性算进**自己 —— 所以 `:not(.dms-labelGrad)` 是 (0,2,0)，**高于**单类的 `.dms-labelGradHigh` (0,1,0)。若只排除最高档那一个类，新加的次高档会命中这条纯色规则、凭特异性胜出，**在需求点名的那个元素上被涂成实心蓝、渐变完全看不见**。同一处还有个测试自身的坑：断言若用 `indexOf('.dms-pillValue:not(.dms-labelGrad)')` 去查，链式写法**包含**这个子串，于是守卫看着通过、实际已不再覆盖第二个类 —— 现在改成**按选择器解析**并逐个核对被排除的类。
  >
  > 实测（把 `-webkit-text-fill-color` **整条删掉**后渲染取样，彩度：渐变 ≥115、纯蓝 ≈187）：小胶囊 115 ✓、圆角矩形档位 115 ✓、对话框「推理强度 + Max」115 ✓ —— 三种载体在**完全不依赖前缀属性**的前提下都仍是渐变。修复前同样的条件下小胶囊会掉到 187（与纯蓝对照组完全一致）。
- **小胶囊动效（仅胶囊形状）**：分两类 —— **一次性动效**（只在浮层内切到最高档时播）与**最高档常驻状态**。
  - 一次性：切到最高档时，先把档位切换本身落定，**延迟 0.2s** 后小胶囊斜向下扫过一道**蓝紫渐变光**（0.8s）。

  | 切到其他档 | 胶囊**立即**开始缩回原大小（`.45s`，**无延迟**） |

  实现要点：
  - **触发条件（重要）**：一次性扫光**只在浮层内把档位切到最高档**时播；**不改变档位、单纯重新打开浮层不会播**。原因是它的元素在浮层里 —— 关浮层会**卸载**、重开时**重新挂载**，而重新挂载的元素会把 CSS 动画**从头播一遍**（`epoch` 没变也没用）。所以除了 `epoch`，还有一个「本次访问是否欠一次动效」的标志 `pillAnimArmed`：只有**真的发生 非最高档 → 最高档 的跃迁、且浮层此刻是开着的**才置位，**浮层一关就清除**。另外档位基准值初始为 `null`（不是 `false`），所以"启动时本来就是最高档、然后打开浮层"也被正确地视为**没有切换**。从浮层之外发生的档位变化（例如切换到自带默认强度的模型）不会置位。
  - **放大是"两个稳定状态之间的过渡"，不是一次性动画**：`"保持放大，切走再缩回"` 用 animation 表达不了（animation 只能往前播一次，然后保持或复原）。所以它写成两个状态 —— 静止态 `scale(1)`、最高档态 `.dms-pillMax{transform:scale(1.14)}`，中间用 transition 插值。**因此胶囊不能再挂 `key`**：重挂的元素没有"上一个值"，会在新尺寸直接出现、过渡永远不播（放大变成跳变）。扫光仍按 `epoch` 重挂，只有胶囊自己的 key 必须去掉。
  - **延迟只能写在最高档那一侧**：CSS 的过渡属性取自**目标状态** —— 目标是最⾼档时用最高档规则的 `transition`（带 `0.2s` 延迟，所以放大等扫光），目标是静止态时用基础规则（**无延迟**，所以离开最高档立即开始缩）。两处都写延迟的话，缩回也会先等 0.2s。
  - **缩放只动 `transform`**，不碰宽高/边距/字号，因此**完全不参与布局**：实测 `Effort` 标签 top 恒为 16.0、滑块 top 恒为 72.0、浮层高恒为 120.0，只有胶囊自身在 1 → 1.14 之间变化。这一点很关键：滑块的内条宽度与手柄位置是**实测几何后缓存**的，如果放大动到布局，就会和这套测量互相打架。
  - **缓动不带过冲**：`cubic-bezier(.4,0,.2,1)` 正好停在自己的端点上（早先用 `cubic-bezier(.34,1.42,…)` 时实测峰值被推到 **1.157**、超过标注的 1.14）。缩放上限 1.25 由测试守住（胶囊很小，超过约 1.2 文字就开始顶到浮层内缘）。
  - **测试按关系推导而不是写死数字**：放大的延迟必须等于扫光的延迟（由扫光规则推导），且**静止态不得有 transform 延迟** —— 这两条一起定义了"跟着扫光长、切走立刻缩"。
  - **小胶囊长度随文字平滑伸缩**：档位名会在 `Low` / `High` / `Max` 之间变长变短，胶囊宽度要**过渡**而不是跳变。`width:auto` 是**不能过渡**的，所以由组件**实测宽度后写成显式 px**，并在文字变化时重放为：清空 → 量出自然宽度 → 恢复旧宽度 → **强制回流** → 写入新宽度。少了那次强制回流，两次写入会被合并成一次样式重算，盒子就**直接跳**过去（测试按"回流必须落在两次写入之间"钉住）。这个逻辑只在**文字真的变了**时才跑 —— 拖动时控件每帧都在重渲染，每帧强制回流是实打实的开销。另外胶囊内容加了 `justify-content:center`，否则盒子会朝右撑、文字看着粘在左边。**横向内边距是长度旋钮**：最初 10px，后来 8px，现在 **6px**（每收 2px，胶囊短 4px；`Max` 时约 48px → 44px → 40px）。测试**不锁**这个具体数值（它会随你的手感反复调），只锁"横向内边距必须大于 0" —— 到 0 文字就会顶到胶囊的圆端。
  - 扫光带是**元素自身**斜切 `skewX(+24deg)`（`\` 方向），因此从左向右掠过时**上缘先进入、高光向下走**，读起来就是"斜向下"；`skewX(-24deg)` 会变成 `/` 方向、视觉上是**向上**扫，符号是有效信息、测试里按**符号**钉住而不只是"有倾斜"。
  - 覆盖层比胶囊左右各宽 25%（留出斜切余量），带子居中（45%–55% 实心、36%/64% 羽化），位移 `translateX(±50%)` 即 ±75% 胶囊宽 —— 正好把带子从"完全在左外侧"送到"完全在右外侧"。**不能用 ±100%**：那会把带子推 300% 胶囊宽，0.8s 里约 400ms 是空跑，实测后半段完全没有光。
  - **延迟写成独立的 `animation-delay:.2s`，不写进简写**：`animation:.8s … .2s` 里第一个时间值是**时长**、第二个才是**延迟**，看错一个就会把 0.8s 的扫光悄悄变成 0.2s。延迟期间不需要 `backwards` 填充，因为基础规则本身就是 `opacity:0`；`forwards` 仍然负责把末帧的全透明保持住。
  - 由**落档检测**触发（`effMode` 稳定到 max 时递增一个 epoch，用 `key` 重挂扫光元素），所以扫光是"每次落到最高档播一次"，而不是拖动经过最高档时按帧狂播；`prefers-reduced-motion` 下扫光动画与胶囊尺寸过渡都关闭。
  - **测试按关系推导而不是写死数字**：放大的延迟必须**等于**扫光的延迟（由扫光规则推导），而静止态**不得**带 transform 延迟 —— 这两条一起定义了"跟着扫光长起来、切走立即缩回去"。
  - **位置**：小胶囊比它的布局位置**下移 5px**（`position:relative; top:5px`）。用 `top` 而不是 `margin-top` 是刻意的 —— 相对定位只是**视觉位移**，不会改变任何盒子的尺寸或后续流：实测 `Effort` 标签 top 16→16、滑块 top 72→72（**都没动**）、浮层总高 120→120（**不变**），只有胶囊 top 37→42。代价是上方间距从 3px 变成 8px、下方从 11px 变成 6px，两者相加仍等于原来的 14px，所以浮层高度守恒。若改用 margin，标签与滑块会被一起推下去，那是另一个改动。
- **浮层头部**：**仅胶囊形状**下改为居中于滑块上方的小胶囊、里面只显示当前档位（如 `Max`），其上方另有一行**当前模型名**，前面是该模型的**品牌 SVG 图标**（用插件已有的 27 个厂商图标，按 `provider/model` 推导品牌，如 DeepSeek 的鲸鱼标；品牌未知时用兜底星标）。这一行是**当前模型**而非固定文案，因为档位已经在下方胶囊里，这行该回答的是"这个档位属于哪个模型"。**拿不到模型名时回退为 `Effort` 且不画图标** —— 在 "Effort" 前面挂一个品牌标会暗示一个并不存在的模型。字号仍是 **14px / 700**（浮层里最大的字号 —— 比它标注的 12px 档位更大更重，因此靠**三号灰色**而非字号来区分"标签"与"数值"；最高档时不参与流光渐变，所以不会比档位本身更抢眼；标签自身无背景、无模糊，毛玻璃下与浮层同样通透）。整行（图标 + 名字）再**整体左移 5px**：用**相对位移**（`position:relative;left:-5px`）而不是 margin —— 相对位移只移动绘制结果、不改变盒子尺寸，所以这一行的宽度、省略号可用空间以及下方内容全都不受影响；用 margin 则会加宽盒子、开始挤占名字的显示宽度。同时 `max-width` 收窄同样的 5px（`calc(100% - 5px)`）为位移预留空间：整行是居中的，超长名字会顶满内边距框，没有这份预留时位移会把 5px 画到面板左边框上。两个数字由测试**互相推导**（预留量必须等于位移量）。图标本身也比下拉菜单的**大**（浮层 **18px**、下拉 14px）—— `size` 本来就是按调用点传入的参数，所以只影响浮层这一处。**18px 正好是该行 `line-height`，也就是上限**：caption 是 flex 行，更高的图标会成为最高项、把行撑高，进而把档位胶囊与滑块一起推下去、整个浮层变高 —— 那是布局变化而不是尺寸微调，测试把上限钉在该行声明的 `line-height` 上。图标与模型名之间**比模型下拉菜单多留 4px**（下拉 2px、浮层 6px）：这 4px 由 caption 自己的 `gap` 提供，而不是去改图标组件共用的 `margin-right` —— 后者会连带把下拉菜单的标记也推开。因为整行是**居中**的 flex 项，加宽 4px 不会让整行平移：它的**中心恒等于头部中心**，只是向两侧各长 2px（标记左移 2px、名字右移 2px）。名字过长时以**省略号截断**：外层是 flex 且 `max-width:100%`，文字单独包在 `dms-pillCaptionText` 里承担省略号，所以**图标永远不被切**，完整名字挂在 `title` 上供悬停查看。圆角矩形形状保持原有左对齐「推理强度 + 档位」文字，且**完全不渲染**这一行

- **关于毛玻璃下的「横向色带」**：有时会看到某一行（常见是标题行）像有一条淡淡底色，比面板其它位置更实。这**不是那一行画了背景**——面板自身只有一层均匀的半透明底色，那一行没有任何绘制；色带是**面板背后的内容**（壁纸/消息列表/输入框）透过玻璃显出来的，透出比例由「毛玻璃透明度」决定。所以背后那块浅、别的区域深，就形成一条带。实测：纯色背景下完全干净，把"上浅下深"的背景放回来就能精确复现。**有效杠杆是提高「毛玻璃透明度」**（20→80% 以上基本压住）；提高「模糊度」基本无效（背景是大面积明暗差，不是一条边）；压缩背景对比度会让面板发闷
- **插件配置卡片**：注册进插件页的 `plugins.item` 槽（条目 `id: dsh-modef`），是**两形态**条目——折叠时贡献一行说明（`view: 'summary'`），展开时由插件页承载表单本体（`view: 'page'`）。含总开关（DSH 官方滑动开关样式）、动画样式、滑块栏形状、浮层毛玻璃与透明度/模糊度微调；草稿改动点「保存」后以**一次原子 `mutate`** 提交到本插件的 profile 条目（`dsh-modef`）。卡片本身不画列表项、标题、箭头与展开控件——那些由插件页提供
- **无缝接管**：开启后以低优先级（-100）遮蔽官方模型选择器，关闭即恢复官方设计
- **拖动性能**：滑块几何一次性测量后缓存（拖动期间不再每事件/每帧读 DOM），指针移动按动画帧合并——避免每次读取都触发同步布局回流

## 安装 Install（这边建议把仓库直接扔给DSH自己安装）

包已发布到 npm（`@magiczerowxy/dsh-modef`），也可直接从 GitHub 安装，统一用官方 `dsh plugin` 命令（二选一）：

### 方式 A：从 npm registry 安装（推荐）

```bash
dsh plugin --profile <profile> add @magiczerowxy/dsh-modef
```

### 方式 B：直接从 GitHub 安装

```bash
dsh plugin --profile <profile> add github:Magiczerowxy/dsh-modef
```

> **`<profile>` 换成你自己的 profile 名**：DSH 桌面版默认用 `desktop`，Web 版用 `web`，其他自定义 profile 写对应名字。不带 `--profile` 时操作默认 profile。
> 命令会自动把包写入 profile 依赖，并因包声明了 `dsh.bundle` 自动加入 layer stack（`dsh.profile.bundles`）。

### ⚠️ 旧版本（< 0.1.1-rc.2 / Desktop < 2.0.2）需要设置白名单补丁

旧版 DSH 的 `settings.describe` 只对硬编码白名单 `WEB_SETTINGS_NAMESPACES` 内的命名空间开放配置。需要在部署的 `@deepseek-ai/dsh-host-apiproxy`（官方决策点）加入 `dsh-modef`：

```
文件：<DSH 安装目录>/resources/app.asar.unpacked/node_modules/@deepseek-ai/dsh-host-apiproxy/lib/index.js

const WEB_SETTINGS_NAMESPACES = [
  // ...
  "web-search-deepseek",
  "dsh-modef"   // ← 添加这一行
];
```

> **DSH 0.1.1-rc.2 / Desktop 2.0.2 及更新版本已移除该白名单**：host 的 `settings.describe` 现在直接暴露全部已注册命名空间，无需任何补丁，本插件的设置卡片自动可用。仅老版本需要上述手动补丁，且 DSH 升级覆盖该文件后需重新添加。

> **0.2.0-rc.1 起还有第二道门 —— 「清单兼容闸门」**：若本包的 `@deepseek-ai/dsh-*` peer 范围没有覆盖你正在跑的 dsh 版本，profile 会在**组合阶段跳过整个 bundle**（现象与排查见上文「0.2.0-rc.1：peer 范围就是开关」）。正式发布的版本都会带上当前运行时行；如果你跑的是更靠前的预览版，要么等这里补上范围，要么在插件管理器（或 `dsh plugin allow-version`）里为这个**精确的包@版本 × dsh 版本**组合开豁免 —— 那是显式接受风险，peer 不匹配确实可能崩或者丢数据。

## 使用 Usage

1. 打开 **设置 → 插件 → 插件配置**
2. 展开「**高级推理等级滑块**」卡片
3. 打开「高级的推理强度选择」，选择最高档动画样式，并按需开启毛玻璃与调节透明度/模糊度
4. 点「**保存**」提交（卡片标题会显示「未保存」直到提交；「放弃修改」丢弃草稿）
5. 输入框的模型下拉变为「模型 + 推理强度」组合控件，拖到最高档观看动画
6. 关闭总开关并保存即恢复 DSH 官方默认设计（`settings.yaml` 中的配置保留）

## 设置项 Settings keys

设置值存在**本插件在 profile 里的条目**中（条目 id 即 `dsh-modef`，由 `cordis.patch.yml` 声明）。0.1.7-rc.1 起不再有独立的 `settings.yaml` 命名空间：文档按**条目**寻址，`configForms.get("dsh-modef")` 即该条目的表单。所有字段都必须声明为 `.volatile()` 才能被写入（见上文「版本兼容」）。

| 键 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `advancedEffort` | boolean | `false` | 高级推理强度滑块总开关 |
| `effortStyle` | string | `spray-flow` | 最高档动画：`spray-flow` / `undertow` / `cosmos` / `sunset`（已删除的 `nyancat` 若仍留在旧 profile 里，读取时**自动回落到 `spray-flow`**，不会报错也不会空着） |
| `trackShape` | string | `rounded` | 滑块栏形状：`rounded`（圆角矩形，保持原有视觉）/ `capsule`（胶囊） |
| `collapseProviders` | boolean | `true` | 模型列表按名称汇集（两级选择器） |
| `glassPanel` | boolean | `false` | 浮层毛玻璃 |
| `glassOpacity` | number | `62` | 毛玻璃透明度 20–90 (%) |
| `glassBlur` | number | `16` | 毛玻璃模糊半径 0–40 (px) |
| `diag` | string[] | *（无）* | **已废弃**：旧诊断缓冲（≤80 条）。写入者已删除（它会造成每 1.9s 的目录重载闪烁，见上文）。保留声明只为兼容已存数据的 profile。**不显示在卡片上**，无默认值 |
| `lastSeatError` | string | *（无）* | 仅供排查：最近一次组合控件崩溃的栈。**不显示在卡片上**，无默认值 |
| `disabledProviders` | string[] | *（无）* | **可选提供商**：在 设置 → 模型 底部的「可选提供商」面板里被关掉的提供商**路由 id**（如 `["workbuddy"]`）。它是本机列表的**镜像**（主拷贝在 `localStorage` 的 `dsh-modef.disabled-providers.v1`，因为开关必须立刻生效）：每次翻转先写本机、再镜像到这里（清空即 `unset`）。模型选择器据此隐藏这些提供商的模型。**不显示在本卡片上**，无默认值；**从不改动任何提供商的 profile** |

> 形状与毛玻璃只影响外观：档位模型、渐变配色与所有动画在两种形状下完全共用。

> **透明度上限为什么是 90 而不是 100**：浮层背景写作 `color-mix(in srgb, var(--dsw-alias-bg-layer-3) var(--dms-glass-op), transparent)`，所以在 **100%** 时这个表达式就等于该底色**本身** —— 与关闭毛玻璃时画的是同一个颜色，而且背景不透明后 `backdrop-filter` **没有东西可模糊**。把两种状态并排渲染确认过：**像素级一致**。于是滑块拉到顶部时「开关没反应」「模糊度没反应」都是**正确观察**，而一个被保存下来的 100% 会跨会话地让这个功能自我失效（用户实际就遇到了：`settings.yaml` 里存着 `glassOpacity: 100`）。收到 90 既保证「开启」**永远看得出半透明**，也让模糊度在**任何**滑块位置都有意义；读取处会 clamp，所以已经存下的 100 会在加载时自愈为 90。测试锁的是「至少留下 10% 的背景可见」这一**可感知**下限，而不只是「小于 100」—— 渲染对比显示 100%/99% 都看不出区别，90% 才读得出背景。

## 浮层为什么不用 `--dsw-specific-menu`（不透明修复）

**模型选择器的浮层必须完全不透明**（需求原文：「模型选择器的浮层不要有透明效果」）。它原本的背景是 `--dsw-specific-menu`，而这个 token 在 **0.1.5-rc.2 里是纯色**（`var(--dsw-alias-bg-layer-3)`），在 **0.1.7-rc.1 里被上游改成了带 alpha 的颜色**：

| 主题 | 0.1.5-rc.2 | 0.1.7-rc.1 |
| --- | --- | --- |
| 浅色 | `var(--dsw-alias-bg-layer-3)` = `#fff` | **`#f8f9fa94`**（alpha `0x94` = **58%**） |
| 深色 | 同上 = `#353638` | **`#30313680`**（= **50%**） |

也就是说**只升级 DSH、不改插件**，模型列表就会自己变成半透明。修法是用回 `--dsw-alias-bg-layer-3` —— 它正是**旧版菜单色所指向的那个 token**：两个主题下都不透明（`#fff` / `#353638`），且**新旧两版都存在**。所以这是**恢复原观感**，不是在这里另发明一个颜色。

同一个 token 还悄悄弄坏了推理强度浮层的一处**既有不变量**：毛玻璃背景是 `color-mix(<底色> P%, transparent)`，把两个 alpha 相乘后，「62%」实际只有 **36%**，上限 90% 也只到 **52%**，而**关闭毛玻璃**时是 **58%** —— 于是开关**反了**，滑块拉满比关闭还透。该表达式一并改用同一条不透明别名，百分比才重新等于「不透明度」。共 5 处引用全部替换（`.dms-menu` / `.dms-sub` / `.dms-panel` / 两处胶囊 `--dms-well`）。

**真实 Chrome 像素证据**（把条纹背景放在浮层下方，采样浮层内部一行；对照组把背景换回半透明 token）：

| 渲染 | 浮层内亮度范围 | 判定 |
| --- | --- | --- |
| 浅色·已发布规则 | 255..255（波动 **0**） | 完全不透 |
| 浅色·对照（半透明 token） | 144..251（波动 **107**） | 透出条纹 |
| 深色·已发布规则 | 53..53（波动 **0**） | 完全不透 |
| 深色·对照 | 24..151（波动 **127**） | 透出条纹 |

对照组的波动 **107** 与理论值一致（58% 的 `#f8f9fa` 覆盖黑白条纹），说明测量确实作用在那层像素上。裸露条纹区每次都读到 `0..255`，用来证明条纹确实位于浮层下方 —— 早先一版探针因为**外边距合并**把整块背景推离浮层，导致两种变体都误报「不透明」，这个对照就是为防它再次发生而加的。
